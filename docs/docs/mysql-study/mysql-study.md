## MySQL 底层学习：B+Tree 索引原理

### 为什么 MySQL 能高效存储和查询？

在我的项目中使用了大量数据库操作，这让我好奇：为什么 MySQL 能如此高效地实现这些存储功能？
答案就在于它的底层数据结构——**B+Tree**。

### B+Tree 的核心特点

-   **只有叶子节点存储数据**：非叶子节点只存“指路信息”（键值），不存数据。
-   **叶子节点之间通过双向链表连接**：这让范围查询非常高效。

### B+Tree 结构示意图 (M=3)

                         [30]                          ← 根节点 (非叶子)
                        /    \
                       /      \
              [10, 20]        [40, 50]                ← 内部节点 (非叶子，只存键)
             /   |   \        /   |   \
            /    |    \      /    |    \
         [5]→[9,10]→[20,25] [30,35]→[45]→[55]        ← 叶子节点 (存数据 + 链表)
          ↓     ↓      ↓       ↓      ↓     ↓
        数据   数据    数据     数据   数据   数据       ← 叶子节点存完整行数据（数据是按顺序存储的）
          ↑_____↑______↑_______↑______↑_____↑
                     所有叶子节点通过双向链表连接

### 查询过程分析

#### 1. 查询 id=5 的数据
1.  从根节点 `[30]` 开始，5 < 30，走左边。
2.  到达内部节点 `[10, 20]`，5 < 10，走最左边。
3.  到达叶子节点 `[5]`，**直接定位**到数据。

#### 2. 查询 id=9 的数据
1.  从根节点 `[30]` 开始，9 < 30，走左边。
2.  到达内部节点 `[10, 20]`，9 < 10，走最左边。
3.  到达叶子节点 `[9, 10]`，**直接定位**到数据。

> **范围查询**：如果要查 `id BETWEEN 3 AND 9`，会先定位到 3，然后顺着叶子节点的链表一直读到 9。读完就停，不用再回到上层节点。

### 这样设计的好处

-   **分层定位，化整为零**：把海量数据的查询，变成一次次在小数据块里的快速定位。
-   **叶子节点链表关联**：既避免了非叶子节点存储过多指针，也省去了范围查询时反复遍历树的磁盘 IO 操作。

### 索引的概念

索引的底层是一颗 B+Tree，一棵由我们指定列的值构成的 B+Tree。主键本身默认就是一颗 B+Tree，所以不需要再为主键单独建索引。

### 组合索引是如何运行的？

以 (name, age, time) 组合索引为例：

                    [name=li, age=40, time=18]                    ← 根节点
                        /    \
                       /      \
 [name=liu, age=15, time=6]   [name=lius, age=25, time=12]       ← 内部节点
             /   |   \        /   |   \
            /    |    \      /    |    \
            叶子节点（存储索引列的值 + 主键）                           ← 叶子节点
          ↓     ↓      ↓       ↓      ↓     ↓
        主键    主键    主键    主键   主键   主键                  ← 用主键去主键索引回表查完整数据
          ↑_____↑______↑_______↑______↑_____↑
                叶子节点之间通过双向链表连接

**组合索引的排序规则**：先按 name 排，name 相同按 age 排，age 相同按 time 排。
这就是“最左前缀原则”的底层原因——跳过第一列就没法利用索引的有序性，底层原因是因为B+树的节点是一个列表，必须从左侧进入，如果没有name字段，查询时就不会进入索引表，从而产生索引失效。

**回表**：辅助索引的叶子节点只存索引列的值和主键。查到主键后，再去主键索引查完整行数据，这叫“回表”。

**注意事项**：
- 索引存储在磁盘上，查询时加载到内存缓存（Buffer Pool）。
- 索引不是越多越好，每次增删改都要同步更新所有索引树，影响写入性能。
- 一般建议单表索引不超过 5-6 个。
