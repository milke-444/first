## MySQL 底层学习：B+Tree 索引原理

### 为什么 MySQL 能高效存储和查询？

在我的项目中使用了大量数据库操作，这让我好奇：为什么 MySQL 能如此高效地实现这些存储功能？
答案就在于它的底层数据结构——**B+Tree**。

### B+Tree 的核心特点

-   **只有叶子节点存储数据**：非叶子节点只存“指路信息”（键值），不存数据。
-   **叶子节点之间通过双向链表连接**：这让范围查询非常高效。

### B+Tree 结构示意图 (M=3)

                         [30]                          ← 根节点 (非叶子)
                        /    \
                       /      \
              [10, 20]        [40, 50]                ← 内部节点 (非叶子，只存键)
             /   |   \        /   |   \
            /    |    \      /    |    \
         [5]→[9,10]→[20,25] [30,35]→[45]→[55]        ← 叶子节点 (存数据 + 链表)
          ↓     ↓      ↓       ↓      ↓     ↓
        数据   数据    数据     数据   数据   数据       ← 叶子节点存完整行数据
          ↑_____↑______↑_______↑______↑_____↑
                     所有叶子节点通过双向链表连接

### 查询过程分析

#### 1. 查询 id=5 的数据
1.  从根节点 `[30]` 开始，5 < 30，走左边。
2.  到达内部节点 `[10, 20]`，5 < 10，走最左边。
3.  到达叶子节点 `[5]`，**直接定位**到数据。

#### 2. 查询 id=9 的数据
1.  从根节点 `[30]` 开始，9 < 30，走左边。
2.  到达内部节点 `[10, 20]`，9 < 10，走最左边。
3.  到达叶子节点 `[9, 10]`，**直接定位**到数据。

> **范围查询**：如果要查 `id BETWEEN 3 AND 9`，会先定位到 3，然后顺着叶子节点的链表一直读到 9。读完就停，不用再回到上层节点。

### 这样设计的好处

-   **分层定位，化整为零**：把海量数据的查询，变成一次次在小数据块里的快速定位。
-   **叶子节点链表关联**：既避免了非叶子节点存储过多指针，也省去了范围查询时反复遍历树的磁盘 IO 操作。
