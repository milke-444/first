#mysql的一些底层学习
#在我的项目中使用了很多数据相关，这让我有些困惑，为什么mysql可以实现这些存储功能
#B+Tree它是数据库的底层设计，它的特点是只有叶子节点是存储数据的，并且每个叶子节点之间互相连接，而其他节点中存储数据的位置信息
                         [30]                          ← 根节点 (非叶子)
                        /    \
                       /      \
              [10, 20]        [40, 50]                ← 内部节点 (非叶子，只存键)
             /   |   \        /   |   \
            /    |    \      /    |    \
         [5]→[9,10]→[20,25] [30,35]→[45]→[55]        ← 叶子节点 (存数据 + 链表)
          ↓     ↓      ↓       ↓      ↓     ↓
        数据   数据    数据     数据   数据   数据       ← 叶子节点存完整行数据
          ↑_____↑______↑_______↑______↑_____↑
                     所有叶子节点通过双向链表连接
让我们分析这棵树的运行过程，我们要查询数据5，此时先进入与30对比，发现此位置信息小于30，从而进入[10, 20]的位置中，5小于10所以冲10进入正好查询到5的数据，如果要查询9的数据，通过[9,10]快速定位到9的数据，这样的设计，可以让大量数据的查询，变成从一个个小块中获取，叶子的关联设计也可以避免非叶子节点存储的位置信息太多，并且可以避免多次遍历树查询，带来更多的io操作。
