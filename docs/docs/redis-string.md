#reids数据结构
#String
String类型的数据结构学习：
一个key--->一个value（String）

常用功能，用于实现缓存，并且可以将同一个用户的多条数据一起存入为一个字符串，保证原子性，但再取用时要记得转换为json。

分布式锁；通过setnx来设置一个key，并发下第一个设置key的可以拿到key，可以做后面的功能，其他的设置key但应为key存在，所以无法拿到锁，但要记得释放锁给其他用户使用，同时也要设置锁的过期时间，使用TTL设置，用于防止阻塞。

也可以存一些视频和图片，但要谨慎。
## 🔗 与项目结合

### 实践点1：详情页缓存
-   **场景**：博客文章详情页，每次打开都要查库（文章、作者、点赞数）
-   **技术**：将博客的标题、内容、作者等打包成JSON，存入Redis String
-   **命令**：`SET blog:detail:1 '{"title":"...","content":"..."}' EX 3600`
-   **流程**：用户请求 → 先查Redis → 有则直接返回 → 无则查MySQL并回写Redis
-   **注意**：更新文章时，需先更新数据库，再删除缓存

### 实践点2：计数器
-   **场景**：文章阅读量统计，每次打开文章阅读量加1
-   **技术**：使用`INCR article:1:views`原子自增
-   **注意**：配合定时任务，将Redis计数同步到数据库

### 实践点3：防缓存击穿锁
-   **场景**：`blog:name`缓存失效时，大量请求同时查库，导致数据库被打垮
-   **技术**：用`SETNX`抢锁，抢到锁的请求负责查库回填，其他请求等待
-   **命令**：`SETNX blog:name:lock:1 "1"` + `EXPIRE blog:name:lock:1 3`
-   **注意**：锁必须设置过期时间，防止死锁
